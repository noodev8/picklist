== Putty Server
cd /apps/picklist/
git pull
rsync -av --delete --exclude='.env' --exclude='node_modules' --exclude='.git' --exclude='tests' --exclude='docs' --exclude='.github' --exclude='venv' /apps/picklist/picklist_server/ /apps/production/picklist_server/
cd /apps/production/picklist_server
npm install
pm2 restart picklist_prod

-- Note the pm2 app is picklist_prod (underscore), not picklist-prod. Restart it by NAME, not by
-- script: several apps on this box run a file called server.js, and 'pm2 restart server.js' matches
-- on the script rather than the app you mean. 'pm2 list' shows the names.

-- Check if needed
npm audit --omit=dev  ->  Should find 0 vulnerabilities


== Flutter app -- NOT deployed by the script above
/apps/picklist/ holds the whole monorepo (picklist_flutter, picklist_library, picklist_server) but the
rsync only ever copies picklist_server/, so the app and library never reach the box.
The phone app is built and distributed separately.
  cd C:\picklist\picklist_flutter
  flutter build apk        (or: flutter build ios)
The server URL is HARDCODED in lib/config/app_config.dart (apiBaseUrl) -- confirm it is the prod
value 'https://picklist.noodev8.com' before building. Older/local URLs are kept commented out
directly above it; a build that went out pointing at a local address is the classic mistake here.
Bump 'version:' in pubspec.yaml and AppConfig.appVersion together.


== Env
/apps/production/picklist_server/.env is excluded from the rsync and must exist on the box:
  DATABASE_URL   postgres connection string (127.0.0.1 on the VPS -- the database is on the same host)
  PORT           3008
  JWT_SECRET     required; without it middleware/auth.js silently falls back to an insecure default
The server has NO default port -- it will not start if PORT is missing.

If you have been running the server locally against prod for testing, you will have pointed
DATABASE_URL at the public host (217.154.35.5). Put it back to 127.0.0.1 before that copy goes near
the box.


== Smoke test after a deploy
On the box or from anywhere:
  curl -s https://picklist.noodev8.com/
      -> {"message":"Welcome to Picklist API"}

Then check both pick lists respond (PIN 2332 = Andreas, 1712 = Summer; these are the only two rows
in the pickpin table):
  TOKEN=$(curl -s -X POST -H 'Content-Type: application/json' -d '{"pin":2332}' \
    https://picklist.noodev8.com/login_pin | python -c "import sys,json;print(json.load(sys.stdin)['token'])")

  curl -s -X POST -H "Content-Type: application/json" -H "Authorization: Bearer $TOKEN" \
    -d '{}' https://picklist.noodev8.com/get_picks
      -> return_code SUCCESS, pick_type "customer"

  curl -s -X POST -H "Content-Type: application/json" -H "Authorization: Bearer $TOKEN" \
    -d '{"pick_type":"amazon"}' https://picklist.noodev8.com/get_picks
      -> return_code SUCCESS, pick_type "amazon"

If the amazon call comes back with pick_type "customer", the box is still running the old code --
the rsync or the pm2 restart did not take. Do NOT let pickers use Amazon mode in that state; the app
detects this exact case and refuses, but only because it checks the echoed pick_type.

Read-only, so both are safe to run against production at any time.


==== Amazon picks -- first deploy of this feature

Adds POST /set_amazon_picked and a pick_type parameter on POST /get_picks. Nothing to configure and
no schema change: it uses columns localstock already has (allocated, location, assigned).

Until this is deployed, the app's Amazon mode shows "Server does not support Amazon picks. It needs
updating." That is deliberate -- the old server ignores pick_type and answers with CUSTOMER picks,
which would otherwise show customer orders under an Amazon heading.

Amazon picking MOVES stock: picking sets location to 'C3-Amazon', unpicking puts it back at the
location the app sends. Nothing is deleted and 'allocated' is never changed, so a mistake is
reversible -- but only while the item is still on screen. Once the list is refreshed a picked item is
gone from it and the only way back is by hand in the database.
'C3-Amazon' is defined in picklist_server/constants.js and in AppConfig.amazonLocation; if it ever
changes it must change in both.
